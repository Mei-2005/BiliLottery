# 架构说明

本文描述运行时结构、接口与关键数据流，便于理解实现。用户向的说明见 [README](../README.md)，前端动效细节见 [前端设计与动效](前端设计与动效.md)。

> 本项目不再维护，也不接受 Issue 与 PR；以下内容仅作实现说明。

## 1. 总览

整个程序是一个 Go `main` 包，前端资源通过 `//go:embed` 打包进二进制，运行时等价于“本地小服务 + 浏览器界面”：

```text
┌────────────────────────────┐        HTTP (127.0.0.1:随机端口)       ┌──────────────┐
│  BiliLottery 进程           │ ◀──────────────────────────────────▶ │  默认浏览器   │
│  ├─ 内嵌 web/index.html     │                                      │  web/index.html │
│  ├─ 抽奖任务 goroutine       │                                      └──────────────┘
│  ├─ 进度/结果内存状态        │
│  └─ B站接口调用 + 头像代理    │ ──────────────▶ api.bilibili.com
└────────────────────────────┘                api.live.bilibili.com
                                              passport.bilibili.com
```

不落盘保存登录凭证、不写数据库、不发遥测。

## 2. 运行时生命周期

1. `main()` 注册路由，监听 `127.0.0.1:0`（由系统分配空闲端口）
2. 通过 `openBrowser()` 尝试拉起默认浏览器（Windows 上依次尝试 `start` / `rundll32` / `explorer`）
3. 启动看门狗：若 10 秒内没有收到任何页面请求，说明浏览器可能没打开，弹出系统提示框给出地址（Windows）/ 日志提示（其他平台）
4. 等待 `shutdownCh` 关闭：
   - `POST /api/shutdown`（界面“退出程序”按钮）
   - `POST /api/ui-closed`（`pagehide` 时用 `sendBeacon` 上报）→ 等待 `uiGoneGrace`（4 秒），期间若没有新的页面请求才退出，因此刷新页面不会误退出
5. 退出前清理二维码临时文件、清空内存中的登录态，然后优雅关闭 HTTP 服务

## 3. 后端结构

`main.go` 内部按以下区块组织（区块间有分隔注释）：

| 区块 | 职责 |
| --- | --- |
| 常量 / 类型 | 接口域名、限速参数、响应结构体、`LotteryConfig` / 进度模型 |
| `App` 与路由 | 进程级状态（登录态、任务互斥、日志、二维码、头像缓存、WBI 密钥、关闭信号） |
| HTTP 处理器 | 状态、登录、抽奖、进度、结果、头像、退出 |
| 抽奖流程 | `runLottery`：校验 → 解析视频 → 收集评论 → 去重 → 核对资格 → 抽取 → 结果 |
| B 站接口 | 视频信息、WBI 签名、评论翻页、二级评论、个人灯牌列表、用户头像 |
| 通用工具 | HTML 转义、头像地址规范化、无偏洗牌、日志 |

并发相关：

- `mu` 保护登录态与 `busy`，保证同一时刻只有一个抽奖任务
- `logMu`、`qrMu`、`avatarMu`、`wbiMu` 分别保护日志、二维码文件、头像缓存、WBI 密钥
- 抽奖任务在独立 goroutine 中执行，HTTP 层立即返回“已开始”

## 4. HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 内嵌的操作页面 |
| GET | `/api/status` | 登录状态、运行日志、是否忙碌 |
| POST | `/api/login/start` | 生成登录二维码并开始轮询扫码结果 |
| GET | `/api/login/qr` | 当前二维码图片（PNG） |
| POST | `/api/lottery` | 提交条件并启动抽奖任务 |
| GET | `/api/progress` | 当前阶段与实时进度（前端 400ms 轮询） |
| GET | `/api/result` | 候选 / 中奖结果（前端 1s 轮询） |
| GET | `/api/avatar?u=<url>&n=<name>` | 头像代理（含缩略、缓存与占位图） |
| POST | `/api/shutdown` | 立即退出 |
| POST | `/api/ui-closed` | 页面关闭通知（延迟确认后退出） |

## 5. 抽奖流程

`runLottery` 的顺序：

1. **参数校验**：BV 号非空且以 `BV` 开头；必须已登录；名额 > 0；条件合法
2. **解析视频**：`/x/web-interface/view?bvid=…` 取 AID、标题、UP 主信息
3. **收集评论**：见下一节；期间持续写入进度（已抓条数、总数、页码）
4. **用户去重**：按 UID 合并，保留该用户的第一条评论；若同一用户多条评论中任意一条带粉丝团灯牌则补上
5. **核对资格**（逐人）：
   - UP 主本人直接排除
   - 等级门槛（可选）
   - 粉丝团灯牌门槛（可选）：按所选判定方式取灯牌信息，缺失或等级不足则淘汰
   - 通过者写入候选列表，同时推送进度供前端绘制
6. **抽取**：`secureShuffle` 使用 `crypto/rand` 实现 Fisher–Yates 洗牌，取前 N 名
7. **结果**：写入内存结果（候选 + 中奖者），前端轮询后播放开奖动效

名额超过候选人数时会自动收敛到候选人数并记录日志。

## 6. 评论抓取

- **游标翻页（主）**：`/x/v2/reply/wbi/main`，需要 `wts` + `w_rid`；WBI 密钥由 `nav` 接口获取，缓存 12 小时
- **页码翻页（回退）**：`/x/v2/reply`（`pn`），用于游标接口失败或早期兼容
- **合并置顶**：每页把 `replies`、`top_replies`、`upper.top` 合并，按 `rpid` 去重
- **二级评论（可选）**：按根评论 `rcount` 调用 `/x/v2/reply/reply`，与父评论成组下发（父先子后），前端据此把回复挂到父弹幕下
- **限速**：每页之间固定间隔；总页数有硬上限防止异常时无限翻页

进度里会同时暴露“已抓取条数 / 总数 / 当前页 / 总页数”，前端用于环形进度与状态文案。

## 7. 粉丝团灯牌判定

判定只关心“是否拥有当前视频 UP 的粉丝团灯牌”，不要求正在佩戴。两种数据源：

| 方式 | 接口 | 覆盖范围 |
| --- | --- | --- |
| 评论区灯牌（默认） | 评论接口返回的 `member.fans_detail` | 最全：拥有灯牌的人评论时都会带上该标签，不受“隐藏灯牌列表 / 仅显示当前佩戴”设置影响 |
| 个人灯牌列表 | `MedalWall`（`target_id=<用户 UID>`，需登录） | 只包含对方公开的灯牌；列表隐藏或仅显示当前佩戴时会缺失 |

`excludeHiddenList` 勾选时切换到第二种方式（评论区数据一概不看），否则使用第一种。选择第二种时会对每位候选用户发起一次请求，因此比默认方式慢。

`fans_detail` 字段映射在 `fansDetail` 结构体中（`medal_id` / `medal_name` / `level` / `intimacy`）。

## 8. 头像代理

前端一律通过 `/api/avatar` 取图，避免跨域与防盗链问题：

- 只允许 B 站图片域名（`hdslb.com`、`bilibili.com`、`biliimg.com`、`bilivideo.com`）及其子域，防止被当作任意请求跳板
- 优先请求 CDN 缩略图（`@192w_192h_1c.webp`），失败回退原图
- 内存缓存：TTL 6 小时、最多 300 条；单张上限 4 MB、超时 15 秒
- 失败时返回按昵称生成的占位 SVG，保证界面不出现破图

## 9. 前端

`web/index.html` 是单文件页面（无框架、无构建步骤），主要模块：

- **状态轮询**：`refreshStatus` / `refreshResult` 每 1s；`pollViz` 在任务运行期间 400ms 一次
- **阶段渲染**：`renderViz` 根据 `stage` 驱动步骤条、聚焦窗口、统计数字与面板内容
- **弹幕（canvas）**：评论先离屏烘焙为位图（`dmBake`），入场时从“收集评论”圆环以小头像气泡飞出并长成完整弹幕，随后按轨道左移；核对阶段快离开左缘的弹幕会“投递”进核对面板（`dmTryDeliver`）
- **核对面板**：`renderFilter` 按 `seq` 增量插入用户条目（头像 + 昵称 + ✓/✗）
- **候选池**：通过者头像以 `flyBubbleFromChip` 从核对面板飞入池子；筛选结束用 FLIP 动画由紧凑布局舒展为宽松布局
- **抽取与揭晓**：`playPoolDraw` 随机高亮并定格，`playWinnerReveal` 把中奖头像抬到固定定位飞行层，按名单顺序错峰飞入目标位置，落位后展开评论
- **无障碍**：`prefers-reduced-motion` 生效时跳过弹幕与大幅动效，直接展示结果

关键参数集中在 `web/index.html` 顶部的常量区（轮询间隔、弹幕速度、队列与池子上限、动效时长等），调整视觉效果时优先修改常量。

## 10. 主要改动入口

以下位置便于自行修改代码（本项目不接收 PR，仅供自行维护时参考）：

- **参与条件**：在 `lotteryRequest` / `LotteryConfig` 中加字段 → `validateConfig` 校验 → 在 `runLottery` 的核对段实现 → 前端补控件与 payload
- **进度字段**：加进 `lotteryProgress` 的 `setProgress` 更新点，并在 `renderViz` 中消费
- **数据源**：把取数逻辑封装为 `App` 方法，保持“失败只记录日志、不阻塞整轮”的约定
- **新增平台**：`openBrowser` / `showNotice` 已有构建标签隔离，补充对应文件即可
