# BiliLottery 前端设计与动效

> 本文档描述页面布局、交互与全部动效参数，可作为复现或移植前端观感的参考（页面布局 + 全部动效）。
> 语言：界面全中文；技术形态：单文件 `web/index.html`（内联 CSS + 原生 JS，无框架、无构建工具）；数据来自本地 Go 后端的 `/api/status`、`/api/progress`、`/api/result`。
> 硬性约束：同时适配浅色/深色（`prefers-color-scheme`）；必须支持 `prefers-reduced-motion:reduce` 降级（关闭全部动画与平滑滚动）；页面为"卡片流"结构。

---

## 一、页面布局

### 1. 全局框架
- `.wrap`：宽 `min(1100px, calc(100% - 28px))`，水平居中，上下留 16px。
- 视觉：浅色主题页面底 `#f4f6f8`、深色 `#111315`；字体 `"Microsoft YaHei", system-ui, ...`。
- 卡片 `.card`：`#fff` 底（深色 `#1b1e22`）、1px 边框（`#e5e7eb` / `#30343a`）、圆角 10px、内边距 `15px 18px`、间距 10px、阴影 `0 2px 7px #0000000d`。
- 主色 `#1677ff`（深色 `#287ff0`）；辅助文本 `#666`/`#aeb4bd`；弱化 `#777`；代码块底 `#f1f3f5`/`#292d33`。
- 全局 `box-sizing:border-box`。移动端（≤700px）：外边距收窄、面板单列。

### 2. 卡片顺序（自上而下）
1）**视频与登录卡**：`h1`"Bilibili 评论抽奖工具"；"视频"区为 4 列网格（`58px | 1fr | 100px | 80px`）：BV 号标签 + 输入框（高 34px、圆角 6px）+ "扫码登录"按钮 + 登录状态文案；下方可展开的二维码区（240×240，`display:none→block`）。

2）**参与条件卡**：标题"参与条件"；条件行用网格 `24px | 220px | 90px`（勾选框 24px + 说明 + 数字输入/留空）："用户等级 ≥"（默认 6）、"UP 粉丝团灯牌 ≥"（默认 1）、勾选框"排除隐藏粉丝团灯牌的用户"（默认不勾）、勾选框"二级评论也参与"（默认不勾）；一段注释（`text-indent:2em` 的段落，说明默认按评论区的粉丝团灯牌判定、勾选后改为只看对方个人的粉丝团灯牌列表）；"中奖名额："行（默认 1）；"开始抽奖"主按钮 + "退出程序"灰按钮。

3）**抽奖实况卡 `#vizCard`**（未开始前 `hidden`）：
   - 头部：标题"抽奖实况" + 状态文案 + 右侧等宽字体时钟。
   - UP 信息行：24px 圆形 UP 头像 + 视频标题（单行省略）。
   - **步骤条**（4 等分）：解析视频 / 收集评论 / 核对资格 / 抽取幸运儿；每步 26px 圆点 + 连接线。当前步：蓝底白字 + 蓝色脉冲光圈（呼吸 `box-shadow` 动画 1.6s 循环）；已完成：绿底绿线；失败：红底。
   - **两栏网格** `minmax(230px,1fr) | minmax(280px,1.35fr)`、间距 12px：
     - 左"收集评论"面板：104px 环形进度（`stroke-dasharray 326.73`，渐变 #3b91ff→#16a34a，0.45s 过渡；总数未知时切"不定态"——局部弧线整体旋转 1.5s/圈）+ 环中心大号计数"条评论"；右侧三行统计：评论总数 / 二级评论 / 去重用户。
     - 右"核对资格"面板：8px 双色进度条（绿 = 通过、红 = 未通过，宽度 0.4s 过渡）；下方"扫描网格"（`minmax(144px,1fr)` 自适应列、高 150px、溢出隐藏），逐条滑入用户 chip：高 32px、22px 头像 + 名字（省略号）+ 标记；符合：绿框绿底；不符合：整体 55% 透明。chip 入场：0.3s 从上方 6px 淡入缩放。

4）**候选池卡 `#poolCard`**（进入抽取阶段前 `hidden`）：池头一行（"X 人符合条件" + 右侧状态文案，如"· 已开奖"）；`.pool` 气泡墙；`#winners` 中奖名单（初始为空）。**注意：不显示"候选池"这类标题。**

5）**运行日志卡**：标题"运行日志" + 深色终端块（高 260px 滚动、圆角 7px、Consolas 13px/1.6、`white-space:pre-wrap`；浅色主题下深底浅字 `#111827 / #d1fae5`）。

6）**两个全屏浮层**（body 顶层）：
   - `#danmu`：弹幕层，`position:fixed; inset:0; z-index:60; pointer-events:none; overflow:hidden`。
   - `#revealLayer`：开奖飞行层，`position:fixed; inset:0; z-index:70; pointer-events:none`。

### 3. 玻璃质感参数（弹幕气泡，亮/暗各一套）
- 亮色：底 `linear-gradient(150deg, rgba(255,255,255,.74), rgba(255,255,255,.46))`、边框 `rgba(255,255,255,.72)`、内高光 `rgba(255,255,255,.5)`。
- 暗色：底 `linear-gradient(150deg, rgba(52,57,65,.62), rgba(28,31,36,.5))`、边框 `rgba(255,255,255,.14)`、内高光 `rgba(255,255,255,.08)`。
- 全局：`backdrop-filter: blur(9px) saturate(1.35)`（含 `-webkit-` 前缀）。canvas 版只取渐变 / 边框 / 内高光，**不做背景模糊**（采样不到背后内容）。
- 拆分：渐变两端色单独放在 `--dm-glass-a` / `--dm-glass-b`（`--dm-glass` 由这两条拼出来），canvas 直接取这两条当渐变停靠色——皮肤只有一处定义。

## 二、评论弹幕系统（收集评论阶段）

> 实现形态：**canvas**。一层 `#danmu`（`position:fixed; inset:0; z-index:60; pointer-events:none; overflow:hidden`）里只放一张 `#danmuCanvas`；每条评论先在**离屏 canvas** 上烘焙成一张位图，主循环每帧只做 `drawImage`。
> 代价：canvas 采样不到背后的页面内容，`backdrop-filter` 的磨砂只能用**同一套渐变 + 边框 + 内高光**近似（气泡整体不透明度 .92，且背后多数时候是纯页面底色，肉眼差别很小）。

### 1. 数据与触发
- 仅"收集评论 / 核对资格"两个阶段显示；进入开奖及之后阶段，弹幕窗口关闭（见 5）。
- 数据随进度接口下发，一条 = 一级评论（昵称/UID/头像/内容）+ 其下若干二级回复；**二级回复必须整楼到齐才随父楼一起显示，挂不上父楼的二级一律丢弃**。

### 2. 气泡结构
```
气泡位图（离屏 canvas，含阴影边距）
 ├ 34px 圆头像（object-fit:cover 的手工版：按 max 比例铺满再居中裁圆；没加载好先铺底色）
 └ 正文
    ├ 头部一行：昵称（600 17px，正文色）+ 7px 间距 + `UID xxx[ · 二级]`（14px 弱化），放不下就换行
    ├ 空 3px 后是评论正文（400 17px，次要色，不限行数、自然换行）
    └ 二级行 ×N：22px 圆头像 + 6px 间距 + `↳ 昵称`（600 14px，次要色）+ `：内容`（14px 弱化），上间距 4px
```

### 3. 气泡视觉
- 胶囊：圆角 17px、内边距 `7px 14px 7px 7px`、头像与文字间距 8px。
- 宽度：按 `max-content` 语义算——先量「完全不折行」的自然宽度，用 `clamp(200, 自然宽, min(92vw,840px))` 定气泡宽（正文可用宽 = 气泡宽 − 63px：头像 34 + 间距 8 + 内边距 21），再按这个宽度折行；中文逐字断、西文按词断、单个超长串（URL）逐字硬断。
- 阴影收小：`0 1px 7px #0000001f`（大模糊阴影在移动时会被看成"拖尾"）+ 顶部 1px 内高光 `inset 0 1px 0 var(--dm-glass-glow)`。
- 基础不透明度 `.92`（每条实际在 0.85~0.97 之间随机）；位图按「设备像素 × 该条随机缩放」烘焙、贴图 1:1，滚动中的文字不会被重采样发虚。

### 4. 滚动与轨道算法（参数为现值）
- 从右往左滚：速度 **380px/s**；起点在屏幕右缘外 `0~140px`（随机错开）。位移按**累计距离**推进（不是墙钟时间），所以标签页切走再回来不会整批瞬移（单帧最多推进 50ms）；行程 = `视口宽 + lead + 气泡宽 + 140px 余量`，尾巴出屏即回收。
- 轨道：每条高 **92px**，顶部留 **16px**，轨道数 = `floor((视口高 − 16) / 92)`；气泡按**精确量出的高度 × 随机缩放**占 1~N 条连续轨道（高度上留 6px 缓冲）。
- 参差：垂直随机抖动 **±6px**（不小于顶部留白）、入场横向随机错开 **0~140px**、随机缩放 **0.96~1.06**、随机不透明度 **0.85~0.97**（基础 .92 由每条覆盖）。
- 发布节拍：每 **90ms** 一拍、每拍 **3 道**；队列积压 >20 时临时放宽到 **6 道/拍**；队列上限 **400**（超出丢最旧）。
- 聚焦避让：聚焦窗口（`.stage-focus`）矩形外扩 10px，与之相交的整条轨道禁用；全部被挡时弹幕排队等待；避免区域在 focus 切换、滚动、缩放时刷新（rAF 节流）。
- 性能要求：**每帧只允许 `drawImage`**。`measureText` 量宽、折行、头像解码、画玻璃底全部发生在"烘焙一次"里（位图失效条件：皮肤 / 视口宽 / 该条随机缩放 / 头像加载完成）；视口尺寸只在开窗与改窗口大小时读一次；单张位图有设备像素上限（超长评论自动降采样，防内存尖峰）；头像按 url 缓存复用（上限 400）。

### 5. 弹幕窗口的开启/关闭
- 开启：进入收集评论阶段（`prefers-reduced-motion:reduce` 时**不开**弹幕，整场演出跳过）。
- 关闭（进入抽取/完成/失败）：丢弃积压队列 → 停止发布 → 整层加 `.closing` 用 0.35s 淡出（淡出期间循环继续画，气泡是"一起淡掉"而不是逐条消失）→ 结束后清屏并停掉 rAF 循环。**保证出结果瞬间画面干净**。
- 开启新一轮时要把 `.closing` 等状态清理干净（`resetDanmu`：清队列与 pending、重建轨道表、`dmStopLoop(true)` 清屏停循环；注意**不能清 `#danmu` 的子节点**，画布就在里面）。

## 三、聚焦与平滑滚动

- 自研 `focusScrollTo(el, mode)`：rAF + smoothstep（先柔、中快、收尾慢）、约 **700ms**；**每帧按元素当前位置重算目标**，因此滚动途中布局变化（收起池子、名单变高）也能平滑跟上；用户 wheel/touchstart 时立即取消。禁止用 `scrollIntoView`。
- 阶段↔窗口映射：解析视频/收集评论 → 收集评论面板；核对资格 → 核对资格面板；抽取+展示 → 候选池窗口。
- 聚焦高亮态 `.stage-focus`：`transform:scale(1.025)`（候选池这类整宽卡片降到 1.015，防止顶出横向滚动条）+ 主题色 1px 描边 + 三层外发光，`z-index:5`。
- 出中奖名单时必须**强制**重新居中（不要因"已经聚焦过"而跳过）；名单展开后若窗口比视口高（`高度×放大倍数 > 0.92×视口高`）才改为"顶部对齐"。

## 四、候选池与抽奖动效

1. **紧凑布局**：34px 圆气泡、6px 间隙；候选数上限约 120 个渲染；气泡入场 `0.38s` 回弹缩放，且必须用 `animation-fill-mode:backwards`（用 both 会永久压住后续高亮的 transform/opacity）。
2. **舒展形变（筛选结束 → 抽取开始）**：用 FLIP 把紧凑布局平滑形变为宽松布局——单个体积按人数选档 **40~72px**、间隙 18px、时长 **620ms**；形变落稳后再开始抽奖（闸门）。
3. **随机抽取动效**（持续 2400ms）：
   - 每 **120ms** 整批"洗牌换新"高亮集合；**任意时刻高亮的数量恒等于中奖名额**（1 个名额就全程只亮 1 个）。
   - 高亮样式：压低其余气泡（42% 透明），点亮者为 2px 主题色描边 + 发光、微微上浮放大；无任何"抽奖中"文字提示。
   - 同时窗口按**非线性曲线越涨越快**地整体放大（1 → 1.16 倍，`cubic-bezier(.45,0,.95,.6)`，时长 = 整个抽取过程；`transform-origin` 顶部居中，底部用 margin 补偿布局占位）。
4. **定格**（900ms）：中奖气泡金色描边 + 金色光晕、`scale(1.22)`；其余压暗 `opacity:.16`；随后进入开奖大轴（见下）。

## 五、开奖大轴（核心观感，按时间顺序）

> 目标：抽奖定格后，中奖头像"滑进"中奖名单的对应位置（非线性、错峰），落位后**卷轴式展开**评论，最终画面与名单完全一致；全程同一头像不同时出现两个。

1. **准备**：渲染中奖名单（预备态 `.pre`：卡片底/边框/阴影透明、头像、序号、正文全部不可见，但**占位保留**，供量取坐标）；按名单序号把中奖气泡迁到 `#revealLayer`（固定定位，冻结宽高与光晕）。
2. **退场**：未中奖气泡 0.3s 淡出缩小。
3. **让位**：+320ms 把整个候选池 `display:none` 收起；用 `offsetHeight`（布局高度，不受缩放过渡影响）重算窗口的底部占位补偿；随后窗口等比放大（上限 **2 倍**，受屏宽约束；`transform-origin:top center`；0.5s 弹性曲线）并按上文规则"聚焦居中/顶部对齐"。
4. **起飞**：先确认"放大的过渡在跑、滚动还在动"都已结束（至少等 560ms 且滚动 rAF 停下），保证落点坐标稳定；随后每张中奖头像按名单序号飞向对应位置——`transform 0.8s cubic-bezier(.5,.05,.2,1)`、错峰 `序号×70ms`、`transform-origin:top left`、位移 + 等比缩放到目标槽位大小。
5. **落位**：全部到达（总时长 ≈ `800 + (n−1)×70 + 90ms`）后清空飞行层，并移除名单预备态——**头像与序号同帧显现**，同时开始展开正文。
6. **卷轴展开**：正文块 `clip-path: inset(0 0 100% 0) → inset(0 0 0 0)`，`0.65s cubic-bezier(.25,.8,.3,1)`，像画卷一样从上往下垂落；前沿压一条 14px 的**卷边阴影**（透明→28% 黑渐变），与裁剪**同曲线、同延迟**一起下滑，收尾淡出；各卡片按 `--open-delay` 依次错峰（第 2 张起每张 +0.09s，第 6 张起统一 0.42s）。**展开必须用裁剪而不是宽度生长**（宽度过渡的中途值会让文字疯狂换行，把卡片撑成细长空条）。

## 六、中奖名单卡片

- 网格：`repeat(auto-fill, minmax(320px×s, 1fr))`、间距 `12px×s`；`s = --w-scale` 按人数收紧（≤4→1；≤6→0.9；≤9→0.8；≤12→0.72；更多→0.64），卡片内所有尺寸与字号都写成 `calc(基准px × var(--w-scale,1))`。
- 卡片（横向 flex）：序号圆标（22px、红底白字）→ 头像链接（64px 圆、**`align-self:flex-start`**，否则会被 flex 拉伸成椭圆；点击跳转该用户主页；hover 上浮 + 蓝色描边）→ 正文块 `.win-body`：昵称（粗体）+ 等级 → `UID：xxx` → 粉丝牌徽标（蓝底胶囊）或"未要求粉丝牌" → 评论块（浅底圆角 8、内边距 8/10、13px）。评论字号缩放公式：总字数 >320 时 `(320 / 总字数)^0.12`，单条 >160 字再额外收一档，下限 0.62。
- 排序：按评论字数**升序**（同字数保持稳定次序），让高度相近的卡片聚在一起、减少网格空白。

## 八、环境行为

- **自动全屏**：加载即尝试全屏；因浏览器要求用户手势，同时挂"首次点击/按键"补触发；不支持或被拒时静默跳过。
- **关闭即退出**：页面关闭（`pagehide`，不含缓存往返）时用 `sendBeacon` 通知后端；后端等约 4 秒确认无后续请求才真正退出（刷新页面不会误杀）。
- **减弱动效**：`prefers-reduced-motion:reduce` 时关闭全部动画、平滑滚动与弹幕演出，直接呈现结果。

## 九、实现约束

1. 弹幕走 canvas：**每帧只做 `drawImage`**，禁止在帧循环里量文字/读布局（`measureText`、`getBoundingClientRect`、`clientWidth` 都只放在烘焙或开窗时）。
2. 位图缓存必须带失效条件（皮肤 / 视口宽 / 该条随机缩放 / 头像加载完成），否则换肤或改窗口大小后会留下残留画面。
3. `prefers-reduced-motion` 下不要跑大轴，直接张榜。
4. 头像**不要克隆**：同一头像迁移用"搬运元素"而不是复制，避免同屏双份。
5. 中奖头像在迁移前应先从候选池淡出，名单出现时再出现，杜绝同屏重复。
6. 名单展开不要用 `max-width/width` 过渡；用 `clip-path`（两端都写显式 `inset()` 才能平滑插值）。
7. 聚焦滚动不要用 `scrollIntoView`；不要指望"已聚焦判重"能帮你重新居中。
8. 判定"窗口是否超高"要等池子收起后、用 `offsetHeight` 量布局高度；避免拿带池子的过期高度或带缩放变换的 `getBoundingClientRect` 误判，导致名单贴顶"偏上"。
9. `.bub` 入场动画用 `backwards` 填充；`.avatar-link` 记得 `align-self:flex-start`。
10. 日志与计数用增量渲染 + rAF 取消（上一轮未完成的数字动画先取消再开新动画）。
