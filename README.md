# BiliLottery

**B 站评论区抽奖工具** —— 填一个视频 BV 号，按用户等级与 UP 粉丝团灯牌筛选评论者，用可视化动效完成抽奖并生成中奖名单。

单个可执行文件即可运行：启动后在本机开一个只监听回环地址的小服务，并自动用默认浏览器打开操作界面。不需要安装 Node、Java 或任何运行时。

> ⚠️ 这是非官方工具，与哔哩哔哩（bilibili）没有任何关联。请自行确认使用方式符合平台规则与当地法律，风险自负。

> 📌 本项目按现状发布，**不再迭代或维护，也不接受 Issue 与 PR**；代码以 MIT 授权，可自由复制、修改与自行维护。

## 功能特性

- **扫码登录**：界面内直接展示登录二维码，登录凭证只保存在进程内存中
- **评论全量抓取**：支持一级评论 + 二级回复，自动合并置顶评论、按 RPID 去重
- **条件筛选**：用户等级门槛、UP 粉丝团灯牌等级门槛、二级评论是否参与、中奖名额
- **粉丝团灯牌两种判定方式**（见下文），可按需排除隐藏了自己灯牌列表的用户
- **可验证的随机性**：使用 `crypto/rand` 做无偏洗牌（Fisher–Yates），不依赖时间种子
- **可视化开奖**：
  - 评论以滚动弹幕呈现在页面上，弹幕从“收集评论”进度环中飞出
  - 核对阶段弹幕会“投递”进核对面板，逐条显示通过 / 未通过及原因
  - 通过者头像从核对面板飞入候选池，池子随后舒展、放大、随机高亮
  - 定格后中奖头像按名单顺序错峰飞入名单，并以卷轴式动画展开评论
- **纯本地运行**：只监听 `127.0.0.1` 的随机端口；无遥测、不上传任何数据
- **关闭即退出**：关闭浏览器标签页后程序自动退出（刷新页面不会误退出）

## 使用须知与隐私

> ⚠️ **切勿在不信任的计算机或网络环境下运行本工具。** 程序运行后不会保留任何数据，但若有恶意软件监视进程、内存或网络流量，运行期间的登录态（`SESSDATA`）仍可能被窃取，从而导致账号被短暂盗用。请只在可信设备与可信网络中使用，风险自负。

**数据流向**

- 服务只监听 `127.0.0.1` 的随机端口，不对外提供访问，也没有遥测、统计或自动更新
- 扫码登录得到的 `SESSDATA` 只存在于进程内存，退出即丢弃；不写入文件，也不会出现在界面日志里
- 评论、昵称、UID、头像只在本机内存中用于筛选与展示，不落盘、不上传；程序不会自动保存中奖名单
- 唯一写入磁盘的临时文件是登录二维码 PNG，位于系统临时目录，退出时删除
- 除哔哩哔哩的接口与头像 CDN 外，程序不访问其他网络地址

**分享与合规**

- 中奖名单里的昵称、头像、UID、评论属于他人的个人信息；对外发布截图、录屏或名单前，请先征得当事人同意或做打码处理
- 抽奖规则、奖品发放与数据使用，需自行确保符合哔哩哔哩平台规则及当地法律（如《个人信息保护法》）
- 本项目只调用平台公开的 Web 接口，不绕过任何隐私设置

## 快速开始

### 方式一：使用预编译版本

从 [Releases](../../releases) 页面下载对应平台的文件：

| 文件 | 平台 |
| --- | --- |
| `BiliLottery-windows-amd64.exe` | Windows 10/11 x64 |
| `BiliLottery-linux-amd64` | Linux x86_64 |
| `BiliLottery-mac-amd64` | macOS Intel |
| `BiliLottery-mac-arm64` | macOS Apple Silicon |

- **Windows**：双击 exe 即可（无控制台窗口，会自动打开浏览器）
- **Linux / macOS**：先赋予执行权限，再运行

```bash
chmod +x BiliLottery-linux-amd64
./BiliLottery-linux-amd64
```

> macOS 首次运行若提示“无法验证开发者”，请在“系统设置 → 隐私与安全性”中允许，或右键选择“打开”。

### 方式二：从源码构建

**环境要求**

- Go **1.27** 或更高版本（见 `go.mod`）
- 可访问 `api.bilibili.com`、`api.live.bilibili.com`、`passport.bilibili.com` 的网络
- 仅 Windows 嵌入应用清单（DPI 感知、权限级别）时需要 [`rsrc`](https://github.com/akavel/rsrc)（构建脚本会自动安装）

**Windows**

```bat
scripts\build-windows.bat
```

**Linux / macOS**

```bash
bash scripts/build-unix.sh
```

**一次编译全部平台**（任意装有 Go 与 bash 的系统）

```bash
bash scripts/build-all.sh
```

产物统一输出到 `dist/`。

## 使用流程

1. **扫码登录**：点击“扫码登录”，用哔哩哔哩 App 扫码并在手机上确认（抓取评论需要登录态）
2. **填写视频**：在“BV号”输入框填入视频的 BV 号（如 `BV1xxxxxxxxx`）
3. **设置参与条件**
   - 用户等级 ≥ N
   - UP 粉丝团灯牌 ≥ N（可关闭该条件）
   - 是否排除隐藏粉丝团灯牌的用户
   - 二级评论是否参与
   - 中奖名额
4. **开始抽奖**：点击“开始抽奖”，等待四个阶段依次完成 —— 解析视频 → 收集评论 → 核对资格 → 抽取幸运儿
5. **查看结果**：中奖名单与对应评论会展示在页面上，运行日志里也能看到每个人的判定原因
6. **退出**：点击“退出程序”，或直接关闭浏览器标签页

> 页面关闭后程序会等待约 4 秒再退出；刷新页面会在等待期内重新发起请求，因此不会误退出。

## 参与条件与粉丝团灯牌

“拥有当前视频 UP 的粉丝团灯牌”有两种判定方式，由勾选项 **「排除隐藏粉丝团灯牌的用户」** 切换：

| 勾选状态 | 数据来源 | 说明 |
| --- | --- | --- |
| **不勾（默认）** | 评论区灯牌（评论接口返回的 `member.fans_detail`） | 覆盖最全：**只要拥有该 UP 的粉丝团灯牌**，无论是否正在佩戴、是否隐藏了自己的灯牌列表，都会在评论区带上灯牌，因此都能被识别 |
| **勾选** | 用户个人的粉丝团灯牌列表（勋章墙） | 只看对方公开出来的灯牌：对方隐藏了灯牌列表时查不到；若设为“仅显示当前佩戴”，则只有佩戴着这枚灯牌的人能被识别 |

两种方式都不要求对方“正在佩戴”该灯牌（勾选方式二时，受对方“仅显示当前佩戴”设置影响除外）。

> 关于隐私：判定只读取平台正常返回的公开数据，不会尝试绕过任何隐私设置；两种方式各有覆盖范围，请按活动公平性要求选择。

## 技术说明

- **后端**是一份 Go 单包程序：内嵌前端资源、启动本地 HTTP 服务、按阶段推进抽奖任务并暴露进度接口
- **前端**是单个 HTML 文件，无构建步骤、无第三方框架；弹幕使用 canvas 离屏烘焙 + 每帧 `drawImage` 渲染
- **状态模型**：`stage = video / comments / filter / draw / done / failed`，前端以 400ms 间隔轮询进度、1s 轮询状态与结果
- **随机性**：抽奖使用 `crypto/rand` 驱动的 Fisher–Yates 洗牌，结果不依赖时间或伪随机种子
- **限速**：评论翻页与灯牌查询之间均有固定间隔，避免对平台接口造成压力
- **安全边界**：服务只监听 `127.0.0.1`，登录凭证仅驻留内存、程序退出即丢弃

接口与数据流的细节见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 常见问题

**浏览器没有自动打开？**
程序没有控制台窗口，所以会在约 10 秒后弹出系统提示框给出访问地址；也可以手动访问运行日志里打印的 `http://127.0.0.1:<端口>/`。

**Windows 提示“已保护你的电脑”，或杀毒软件报毒？**
程序没有做代码签名，SmartScreen 会对所有未知发布者的 exe 弹出这个提示。点“更多信息 → 仍要运行”即可；杀毒软件误报同理。如果不放心，可以按上文从源码自行构建。

**提示“请先扫码登录”？**
抓取评论必须携带登录态，请先完成扫码登录。

**抓取很慢？**
评论按页抓取且每页之间有间隔，评论量大的视频需要等待；这是为降低触发平台风控的概率。

**日志里有人被判“没有该 UP 的粉丝团灯牌”，但我在评论区确实看到他带牌？**
请确认勾选状态：勾选“排除隐藏粉丝团灯牌的用户”后只认对方公开的灯牌列表，会漏掉隐藏列表的人；取消勾选即可按评论区灯牌判定。

**接口返回 `-352` / `-412` 等错误？**
通常是访问频率或风控导致，建议稍后重试、降低频率，或更换网络环境。

**改了 `web/index.html` 不生效？**
前端通过 `go:embed` 编译进二进制，修改后必须重新构建。
